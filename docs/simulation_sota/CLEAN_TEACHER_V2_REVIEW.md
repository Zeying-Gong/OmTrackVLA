## 实际缓存网格发现

固定 `evt_bench/rearrange_sim_v2.py` 的 `_load_navmesh()` 在初始化后按运行时 scene ID 加载 `data/scene_datasets/navmeshes/zR6kPe1PsyS.navmesh`。原计划只覆盖场景旁的 `zR6kPe1PsyS.basis.navmesh`，遗漏该实际缓存文件。

缓存网格 SHA256 为 `32c18267379578ee878c82477d2eac80ad987364dd78ebdf72f96bd9a2bf7708`，解析到 `/data/nfs/share/evt_bench/navmeshes/zR6kPe1PsyS.navmesh`。**此哈希是采集后测得，V1/V2 未在运行前绑定它；不把当前文件内容冒充为已封存的历史运行内容。** 源码加载路径、保存的 waypoint 和当前网格复查支持这一诊断，但仍需下一版在运行前后绑定实际缓存，并记录实时查询，补齐证据。

当前缓存网格上的 124 帧中，23 帧机器人和目标都在 island 0，101 帧机器人在 island 1、目标在 island 0。帧 22 首次映射到 island 1，帧 25 短暂映回 island 0，帧 29 已完全可导航地处于 island 1，之后持续不连通。起点最大水平吸附距离 0.15508 m，最大垂直修正约 1.51e-6 m。**单独吸附起点不能修复本例。**

固定 `BaseVelNonCylinderAction.collision_check()` 对中心及前后偏移点执行 `step_filter`；允许 sliding 时，选择修正最大的偏移点，把其位移用于整个机器人中心。当前允许旋转时滑移，因此 yaw-only 动作也可能产生平移。该机制与无平移命令时仍出现的位置变化一致。已有退避候选虽检查路径可达，最终执行后的中心却未受同一连通性约束，须针对实际动作结果加约束；不能静默替换成相邻网格来掩盖问题。

## 下一版修复与验收边界

V3 保持同一样本、种子、目标、环境和 V2 教师参数，绑定实际缓存网格。只在教师侧增加基于真实动作运动学和 `collision_check` 的候选预测，覆盖平移、转向和滑移，拒绝从目标可达分量进入不连通分量的预测结果。预测必须不推进机器人、动作控制器或世界时钟；记录所有候选、拒绝原因、预测/实际姿态及残差。无可安全预测候选时明确记录失败，不瞬移机器人、不改网格。

修复有效性必须由下一次有界真实运行验证，不能从 CPU 测试推定跟随成功。这是使用 GT/pathfinder 的教师采集修复，不是部署侧主动搜索完成证明。已核验的 RGB/语义标签可另行申请明确的感知诊断用途；失败动作不可作为成功示范混入动作模仿训练，V2 原始准入标志继续全部为 false。
