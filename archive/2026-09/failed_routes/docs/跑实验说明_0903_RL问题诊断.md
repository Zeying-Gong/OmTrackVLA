# V27 RL 问题诊断与修复说明（2026-09-03）

## 结论先行

V26 不是“训练完但模型学坏了”，而是正式 RL 实验没有完成：只跑到
`update=11`，没有 validation、best checkpoint 或 final checkpoint。每张卡每次
只有 4 个 transition，到 update 11 每个 rank 约 44 个 transition，远小于一个
300 步跟踪 episode，不能据此判断 PPO 是否超过 IL。

同时，V26 的 reward/环境协议有三个确定问题：

1. `track_train_*.yaml` 的主行人像素阈值是 10000，而正式推理口径是 3000；RL
   优化的 `human_following` 和最终 STT/AT/DT 指标不是同一个判定。
2. EVT-Bench 的 `human_collision` 实现使用 `distance < 0.5`，并且第一次触发后
   `_ever_collide=True`，后续每一步都保持 1。V22 每一步扣分，等价于一次碰撞
   污染整个 episode。
3. V24 在 `TrackEnv.step()` 已经生成处理后的观测后，又调用一次
   `sim.get_sensor_observations()`。这会重复渲染，并造成 DDP rank 速度严重不一致。

V27 是新入口，不覆盖 V22–V26。它先修复协议，再进行短 probe；probe 通过后才
考虑正式训练。

## V27 改动

新增文件：

- `hybrid_flux/train_online_rl_v27.py`：基于 V26 的新 runner。
- `hybrid_flux/online_rl_utils_v27.py`：新的 reward。
- `run_online_rl_v27_probe.sh`：单卡、8 步 horizon 的协议 probe。
- `run_online_rl_v27_formal.sh`：8 卡正式候选命令，默认不自动启动。
- `tests/test_online_rl_v27.py`：reward 的纯 Python 单测。

具体行为：

- train/val 在 runner 内都把主行人 detector threshold 统一为 3000；默认不把
  detector、bbox、panoptic、目标位姿或 oracle action 输入模型。
- 优先使用 `did_multi_agents_collide` 的当前步接触事件；旧环境没有该字段时，
  对 `human_collision` 只取 rising edge。
- reward 保留官方 `human_following`、2 米距离 band、距离进展和重新捕获奖励，
  增加 `<0.85m` 的安全距离惩罚；碰撞不再永久重复扣分。
- PPO 增加 Linear-RF IL 分布的 latent-space KL anchor。默认 `V27_RL_ONLY=1`，
  只训练 `rl_context`、`rl_residual_head`、`rl_value_head`、`rl_log_std`，固定
  原有 FLUX/IL action path，先验证 recovery residual 是否真的有正向作用。
- `TrackEnv.step()` 返回的已处理 RGB-D 直接进入模型，不再额外读取 raw sim
  sensor。观测诊断写入 `obs_diag/`，只记录 hash，不把 truth 送给 policy。
- partial rollout 不再伪装成 completed episode；PPO 的 GAE bootstrap 逻辑不变。

## 推荐执行顺序

远端项目目录：`/data/nfs/share/OmTrackVLA`。

先把新增文件同步到远端，再运行 probe：

```bash
cd /data/nfs/share/OmTrackVLA
bash /data/nfs/share/OmTrackVLA/run_online_rl_v27_probe.sh
```

probe 只验证：导入、观测 key/shape、统一阈值、reward 组件、KL anchor、单次
checkpoint、validation plumbing。它使用 8 步 horizon，不是 STT 指标。

检查以下文件后再正式运行：

- `experiments/flux_ilrl_evt_train_0903_v27_probe/online_rl_history.jsonl`

## 结果判定标准

不能只看 rollout return。至少要在同一评测协议下比较 IL checkpoint、V27 best
checkpoint 和 rule-based/modular baseline 的：

- Success rate
- Tracking rate
- Collision rate
- 平均跟踪距离
- Recovery success rate
- Recovery time

只有 V27 完成足够 update、出现 validation best，并且在 STT/AT/DT 固定评测上
重复优于 IL，才把它写入主指标汇总表。V26 的 update10 仍只作为诊断样本，不能
标记为正式 RL 结果。

## 后续 decoder 解冻

V27 默认先固定 FLUX/IL action path，是为了隔离“奖励/采样协议是否正确”和
“大模型参数是否适合 online update”这两个变量。若 RL-only warm phase 在
validation 上有稳定收益，再单独设置 `V27_RL_ONLY=0` 并使用很小的
`--unfreeze-decoder-last-n` 做第二阶段消融；第二阶段必须单独输出目录和指标，
不能覆盖 V27 RL-only 结果。
