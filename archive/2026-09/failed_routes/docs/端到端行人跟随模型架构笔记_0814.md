# 端到端行人跟随模型架构笔记

更新日期：2026-08-14

## 方法概述

该方法是一个 RGB-only 部署的统一目标条件导航策略，首要任务是目标行人跟随，并希望通过多任务训练扩展到 PointNav 和 Instance-ImageGoal/ImageNav。模型将当前 ego RGB、压缩的历史视觉/运动记忆、可选目标图像和可选 PointGoal 编码为 token，通过 DINOv2-S/14 与轻量 eVGGT 风格的 frame/global alternating Transformer 融合，统一预测未来 8 个 ego-centric waypoint。训练时，额外使用显式轨迹动作条件的前向动力学和逆动力学作为辅助任务，用未来 DINO 语义变化和 Depth Anything V2 伪深度变化约束共享表示；这些辅助分支在部署时可全部不用或删除，从而提升整体推理速度。

## 1. 设计边界

### 1.1 主要目标

- 根据指定人物而非画面中最显眼的人生成动态跟随轨迹。
- 仅根据持续更新的 PointGoal 导航到静态目标点。
- 根据人物、物体或地点的目标图像匹配指定实例并导航到其附近。
- 同时学习目标身份、场景几何、ego motion、动态目标运动和可通行空间。
- 支持 target-image-only、point-only 和 target image + PointGoal 三种条件形式。
- 训练可使用离线大模型产生伪标签，部署不依赖 Depth Anything V2 或未来观测。

### 1.2 与原始 OmTrackVLA 的区别

原始 OmTrackVLA 主要使用 31 帧 coarse 历史 token、1 帧 fine 当前 token 和文本指令，没有真正使用 target crop、PointGoal 或 depth。本方法改为：

- 使用少量历史帧构建持久压缩记忆，避免 31 帧全 patch global attention。
- 显式引入 target identity token 和可选 PointGoal token。
- 使用 eVGGT 风格的几何时空 Transformer，而非 Qwen 文本主干。
- 用仅训练时的 future semantic/depth dynamics 将几何知识蒸馏到 RGB policy。

### 1.3 与 WALA 的关系

本方法仅参考原版 WALA 的 semantic-geometric future supervision，不使用其 future-conditioned latent-action transition bottleneck、`z_oracle` 对齐或两阶段 LAM 预训练。

原因是导航 ego motion 可以从里程计、VIO、VSLAM 或 VGGT 恢复为带置信度的 SE(2) 轨迹，因此可直接学习显式可执行动作，无需用 latent action 替代缺失的动作标签。

## 2. 整体架构

```text
Current Ego RGB -> DINOv2-S/14 patch encoder ------------------+
                                                                |
History Context Cache ------------------------------------------+
  |- explicit motion tokens: online odometry/VIO/VSLAM          |
  `- compressed RGB scene-memory tokens                         +
                                                                |
Target Image (Person/Object/Place) -> identity tokens + validity/confidence ----+-> Token Fusion
                                                                |       |
Optional PointGoal -> goal tokens + validity/confidence/age ----+       v
                                                        Lightweight eVGGT-style
                                               [Frame Attn -> Global Attn] x 4
                                                                |
                                                       shared policy state h_t
                                                        /                 \
                                                       /                   \
                                      Waypoint Policy Head           training-only heads
                                               |                     /              \
                                   8 ego-centric waypoints   Forward Dynamics   Inverse Dynamics

Training-only targets:
  trajectory a* ---------------> waypoint / forward condition / inverse target
  future RGB -> frozen DINO ----> future semantic residual target
  future RGB -> frozen DA-V2 ---> future log-depth residual target
```

## 3. 部署输入与编码

### 3.1 当前 RGB

部署主输入是单张当前 ego RGB，不需要真实 depth 或在线伪 depth。RGB 先经 DINOv2-S/14 ViT 变成 patch tokens：

```text
I_t -> DINOv2-S/14 -> F_t in R^(P x 384)
```

DINOv2 在这里是 RGB encoder，不是额外输入模态。第一版建议冻结 DINOv2-S；稳定后再消融解冻最后 1--2 个 block。

### 3.2 历史上下文缓存

不将长历史的所有 patch 重复输入 global attention。部署时维护一个在线更新的 `History Context Cache`，包含：

- `Motion Tokens`：过去若干步的 `(v_x, v_y, omega)` 或相对 SE(2)，来自里程计、VIO 或在线 VSLAM。
- `Scene Memory Tokens`：对过去 RGB patch features 做 temporal pooling/resampling 得到的少量场景记忆 token。

训练时可使用每个 clip 的 4--8 帧稀疏历史模拟 cache 更新。原始过去帧不作为长序列再次进入主干，以限制 global attention 的二次复杂度。

### 3.3 目标图像与目标类型

人物首帧 bbox、静态物体 crop 或 ImageNav goal image 与 RGB encoder 共享或部分共享权重，产生：

```text
target image -> identity tokens + target_type + target_valid + target_confidence
```

PointNav 等目标图像缺失的任务使用独立可学习 null token，不使用全零 token 混淆“缺失”与有效特征。

### 3.4 PointGoal

PointGoal 使用轻量 MLP/tokenizer 编码：

```text
(x, y, range, bearing, uncertainty, age, valid) -> goal tokens
```

PointGoal 为可选条件，用于极端遮挡、目标短时离开视野或 UWB/relative localization 可用的场景。不应固定视觉或 PointGoal 的永久优先级，而应依据 validity、confidence、age 和时序一致性融合。

## 4. eVGGT 风格主干

### 4.1 结构

主干由两类 Transformer self-attention 交替组成：

- `Frame Attention`：在单帧/当前 token 集合内建模人物、障碍物与局部空间关系。
- `Global Attention`：在当前 patch、历史 memory、identity 和 goal tokens 之间融合跨时刻/跨模态信息。

第一版使用 eVGGT student 规模：

```text
DINOv2-S/14 patch encoder: 22.06M
4 frame-attention blocks:   4.74M
4 global-attention blocks:  4.74M
hidden dimension:           384
attention heads:            4
MLP ratio:                  2
2D positional encoding:     RoPE
aggregator total:            about 31.54M parameters
```

`depth=4` 表示 4 组 `[Frame Attention -> Global Attention]`，即实际共 8 个 Transformer blocks。

### 4.2 输出表示

使用少量 policy queries 从融合 token 中汇聚出 `h_t`，而不必丢弃 patch-level features。

- `h_t`：waypoint、forward dynamics 和 inverse dynamics 共享的紧凑策略表示。
- `F_t`：保留空间网格的 patch features，用于训练期 dense semantic/depth/free-space prediction。

## 5. 显式导航动作

对每个 clip，将仿真 ground truth、里程计或离线 VGGT/VSLAM 轨迹统一转换为 8 步 ego-centric action chunk：

```text
a* = [(delta_x, delta_y, sin(delta_yaw), cos(delta_yaw), optional_speed)_k]_(k=1..8)
```

同时保留：

- 累计 SE(2) pose。
- 每步 `action_valid`。
- 每步 `action_confidence`。
- 时间对齐和尺度来源。

伪轨迹置信度由跟踪内点率、重投影误差、尺度可观性、轨迹连续性和机器人运动学合法性综合构造。

## 6. 三个任务分支

### 6.1 Waypoint policy：部署主分支

```text
h_t -> MLP waypoint head -> a_hat in R^(8 x D_a)
```

第一版使用 MLP head。只有在实验确认绕障多解成为主要误差来源后，再考虑 mixture/diffusion/DiT action head。

### 6.2 Action-conditioned forward dynamics：仅训练

该分支是并行辅助任务，不是 waypoint 之后的部署串行模块：

```text
(h_t, F_t, a*) -> ForwardDecoder
                 |- predicted future DINO residual
                 |- predicted future log-depth residual
                 |- predicted local free-space/occupancy residual
                 `- optional target relative state/visibility
```

训练时默认使用轨迹标签 `a*` 作为 teacher-forced action condition，不使用当前不稳定的 `a_hat`，避免动作预测误差污染 future loss。这与先前 Dyna2/forward-dynamics 实验的公平设置一致：辅助 head 使用 current state + ground-truth action chunk 预测 future state。

前向动力学应概念上分解为：

- `Ego-induced dynamics`：由机器人动作导致的相机视角、场景流和可通行空间变化。
- `Person dynamics`：指定目标人物自身的位移、速度和可见性变化。

### 6.3 Inverse dynamics：仅训练

```text
(h_t, stopgrad(h_t+H)) -> InverseHead -> recovered action chunk a_inv
```

`h_t+H` 由共享编码器对训练期未来 RGB 编码得到。Inverse head 恢复局部 waypoint chunk、累计 SE(2) transform 和可选速度/角速度，以保证共享表示保留可控 ego motion。

## 7. 训练期目标生成

### 7.1 DINO 语义目标

```text
future RGB -> frozen DINOv2 target encoder -> F_t+k^teacher
Delta F* = stopgrad(F_t+k^teacher - F_t^teacher)
```

DINOv2 同时可以是部署 RGB encoder 的初始化和训练期 frozen teacher。两者是角色不同的编码路径，不是两种输入模态。

### 7.2 Depth Anything V2 几何目标

```text
current/future RGB -> frozen Depth Anything V2 -> pseudo relative depth
Delta D* = normalized_log_depth_future - normalized_log_depth_current
```

Depth Anything V2 仅用于离线预计算训练 target，不在部署路径中产生 depth token。其单目输出主要是相对深度，因此：

- 对 current/future 使用同一 clip-level 归一化，保留变化量意义。
- 使用 log-depth residual 和空间 gradient loss。
- 仅在经过相机高度、地面平面、VSLAM 尺度或少量真实 depth 校准后，才用它构造米制 occupancy/碰撞距离。
- 未校准时将相关输出称为 relative free-space/occupancy，不声称 metric occupancy。

### 7.3 目标人物区域监督

全局 future loss 易被墙面、地面和 ego motion 主导。将目标 bbox/mask 缩放到 patch grid，对指定人物区域加权：

```text
patch_weight = 1 + alpha_target * target_mask + beta_free * local_free_space_mask
```

还需要 target-swap negative：将同一历史观测配对错误 target crop，检验 identity condition 是否真正控制人物状态和 waypoint 预测。

## 8. 损失函数

```text
L = L_waypoint
  + lambda_fd     * L_forward
  + lambda_inv    * L_inverse
  + lambda_target * L_target
```

```text
L_waypoint = confidence(a*) * masked_smooth_l1(a_hat, a*)
           + lambda_se2 * L_cumulative_SE2

L_forward = L_DINO_residual
          + alpha_depth * L_log_depth_residual
          + beta_grad   * L_depth_gradient
          + gamma_free  * L_relative_free_space
          + delta_state * L_target_relative_state

L_inverse = confidence(a*) * masked_smooth_l1(a_inv, a*)
```

初始损失权重保守设置，保证 `L_waypoint` 主导优化；再根据各分支 gradient norm 和独立消融调整辅助权重。

## 9. 单阶段训练

所有可训练模块在同一阶段联合优化，不进行 WALA 式 LAM 预训练。

### 9.1 样本类型

- 仿真/真机高置信轨迹：启用所有损失。
- VGGT/VSLAM 伪轨迹：按 `action_confidence` 连续降权 waypoint、forward-action-condition 和 inverse loss。
- 无可靠尺度/轨迹：设置 `action_valid=0`，屏蔽 action-related loss；可选保留不依赖动作的 identity/visibility 监督。

第三类样本仍在同一训练阶段中，只是通过 validity mask 选择有效损失。

### 9.2 鲁棒性增强

- 对 target crop 和 PointGoal 分别进行 random modality dropout，但不无约束地同时删除所有目标条件。
- 对 PointGoal 注入高斯噪声、时延、漂移和丢包。
- 随机污染视觉目标或 PointGoal 中的一种，构造冲突样本，训练 confidence-aware fusion，不强制永久优先视觉。
- 模拟连续遮挡、ReID 错误、历史 cache 丢失和在线里程计中断。

## 10. 部署路径和规模

部署时仅保留：

```text
current RGB encoder
+ history cache updater
+ target/PointGoal encoders
+ lightweight frame/global Transformer
+ waypoint head
```

删除：

- frozen DINO target encoder 的未来帧路径。
- Depth Anything V2。
- Forward Dynamics Decoder。
- Inverse Dynamics Head 和 future-state encoder path。

参数量粗估：

```text
eVGGT visual aggregator/backbone: about 31.5M
target/PointGoal/history fusion:   about 1--3M
waypoint head:                     about 1--3M
deployment total:                  about 34--38M
```

实际延迟主要受 RGB 分辨率、当前 patch 数、history memory token 数和 global attention token 总量影响，不能只根据参数量判断。

## 11. 必做消融

1. `Policy only`：仅 waypoint loss。
2. `+ Forward DINO`：仅语义 future residual。
3. `+ Forward DINO + Depth`：增加伪深度几何监督。
4. `+ Inverse dynamics`：检验 ego-motion 辅助监督。
5. `Teacher-forced a* vs predicted a_hat`：确认 forward dynamics 动作条件设计。
6. `No history vs raw-frame history vs compressed cache`。
7. `Visual-only vs PointGoal-only vs hybrid`。
8. `Global future loss vs target-region-weighted future loss`。
9. `Frozen DINOv2-S vs partial fine-tuning`。

## 12. 行人跟随基础指标

除平均跟随成功率外，报告：

- Tracking Rate、Collision Rate、目标距离误差和轨迹平滑度。
- 长遮挡、多人交叉、目标重现和 ReID 错误。
- PointGoal 丢包、延迟、漂移和跨模态冲突。
- 新人物外观、新场景、摄像头扰动和空间 OOD。
- target-region/background-region future prediction error。
- 部署参数量、显存、单步延迟和 history-cache 更新开销。

## 13. 希望完成的统一导航任务

模型共享同一个 RGB/history backbone 和 waypoint 输出空间，通过 `task_type`、目标模态 validity 和 task-specific loss mask 区分任务。

### 13.1 Target Person Following

输入：

```text
current/history RGB
+ target person crop
+ optional relative PointGoal
+ task_type=person_follow
```

目标是在避障的同时持续跟随指定动态人物并保持合理距离。该任务需要处理目标运动预测、多人物身份区分、长遮挡、目标重现和 PointGoal/视觉冲突。

### 13.2 PointNav

输入：

```text
current/history RGB
+ no target image (learnable null token)
+ PointGoal(x, y, range, bearing)
+ task_type=pointnav
```

目标点在世界坐标中静止，但机器人运动后 PointGoal 必须在每一步重新变换到当前 ego frame。PointNav 不需要预测目标自身运动，因此目标动力学比行人跟随简单；但远距离、非视线目标仍需要空间记忆、长程绕障和 stop decision。

### 13.3 Instance-ImageGoal / Object-Crop Navigation

输入：

```text
current/history RGB
+ target object/person/place image
+ optional PointGoal
+ task_type=imagegoal
```

这里需要把“目标条件的图像形式”和“导航难度”分成两个相互独立的维度。

目标条件的图像形式：

- `Standard ImageNav goal view`：输入从目标地点或目标观察位姿拍摄的完整 RGB 图像，模型需要到达与该场景视图对应的位置；通常不提供 bbox。
- `Instance-ImageGoal`：输入指定人物或物体实例的参考信息。推荐使用“完整参考图 + bbox/mask”，同时编码全图场景 token 和 bbox/mask 对应的 ROI identity token；也可以只输入 crop，但 crop 应统一 resize/pad 后编码。
- 图像是否与当前 RGB 同尺寸不决定任务类型。将 bbox 区域保留在全尺寸画布中仍然是在提供显式实例提示，因此更接近 Instance-ImageGoal，而不会仅因分辨率相同就自动成为标准 ImageNav。

导航 episode 的难度：

- `Visible-target approach`：目标从起点开始始终或大部分时间可见，主要检验实例匹配、局部避障和视觉伺服。
- `Full navigation/search`：目标起初可以不可见，需要搜索、跨房间导航、历史记忆、排除相似干扰实例并判断停止。使用完整 goal-view 时对应 Full ImageNav；使用带 bbox/mask 的指定实例参考图时，更准确地称为 Full Instance-ImageGoal。

因此，只把人物参考 crop 换成当前可见的静态物体参考图，而训练轨迹中没有目标初始不可见、跨房间搜索和错误实例干扰，只能证明 visible-target instance approach。反过来，即使输入的是 crop，只要训练和评测包含完整的隐藏目标搜索过程，它也可以构成 Instance-ImageGoal 导航，只是不应与标准、无 bbox 的 ImageNav 协议混称。

## 14. 训练数据需求

### 14.1 统一样本格式

所有任务尽量转换为相同结构：

```text
task_type
current_rgb
history_rgb_or_cache
history_motion
target_image
target_type
target_valid / target_confidence
pointgoal
pointgoal_valid / pointgoal_confidence / pointgoal_age
trajectory_or_waypoints
action_valid / action_confidence
future_rgb
target_mask_or_bbox
stop_label
success_label
```

不是每个样本都需要所有字段。缺失输入使用独立 null token，缺失监督通过 validity mask 屏蔽，不能用全零张量隐式表示所有缺失情况。

### 14.2 行人跟随数据

数据来源优先包括：

- EVT-Bench/Habitat 中的 STT、DT 和 AT 人物跟随轨迹。
- 当前 OmTrackVLA 仿真数据和成功 episode。
- 具有机器人位姿、目标人物位姿、目标 bbox/mask、碰撞和可见性记录的新增 Habitat rollout。
- 可选真机 RGB、里程计/VIO/UWB 和目标跟踪数据。

每个样本需要目标人物 crop、未来机器人轨迹、目标相对状态、可见性和碰撞标签。应覆盖多人交叉、外观相似人物、长遮挡、目标停止/转向/加速和目标重新出现。

### 14.3 PointNav 数据

在 HM3D/MP3D/Gibson 等场景中随机采样可达起点和静态目标点，通过 Habitat shortest-path follower、规划器或已有专家轨迹生成训练 episode。

数据构造必须包括：

- 近距离与远距离目标。
- 目标在视线内与视线外。
- 单房间与跨房间。
- 直线路径与必须绕障的路径。
- 每步更新的 ego-centric PointGoal。
- 最终 stop action/到达标签。
- geodesic distance、shortest-path length 和 collision 标签。

不能只用“目标点在当前视野前方”的简单样本，否则模型会退化成局部 PointGoal 控制器。

### 14.4 ImageGoal/Object-Crop 数据

在同一 3D 场景中选择目标实例或目标地点：标准 ImageNav 保存目标观察位姿的完整 goal-view；Instance-ImageGoal 保存完整参考图及 bbox/mask，并可从中派生统一 resize/pad 的 ROI crop。随后从其他起点生成到达该目标的专家轨迹。

数据需要覆盖：

- 目标当前可见和初始不可见两种设置。
- 同一实例的跨视角、尺度、光照和遮挡变化。
- 同类不同实例与视觉相似物体作为 hard negatives。
- 目标曾经可见后再次离开视野。
- 跨房间搜索、错误房间和回退轨迹。
- 目标 mask/bbox、目标位置和可靠 stop label。
- 不包含可从文件名、固定相机或场景ID泄漏答案的捷径。

如果只有目标当前可见的局部接近轨迹，应将结果命名为 visible-target approach。是否属于标准 ImageNav 或 Instance-ImageGoal 由目标条件语义决定：完整、无实例标注的 goal-view 对应 ImageNav；带 bbox/mask 或独立实例 crop 的指定实例参考对应 Instance-ImageGoal。

### 14.5 训练期语义与几何伪标签

对所有带时间连续 RGB 的任务，可离线预计算：

- Frozen DINOv2：current/future semantic feature residual target。
- Frozen Depth Anything V2：clip-consistent normalized log-depth residual target。
- VGGT/VSLAM：相机轨迹、尺度/置信度和可选局部几何。
- 检测/分割/ReID模型：目标 bbox、mask、identity confidence 和 visibility。

这些模型只负责生成训练 target，不进入默认 RGB-only 部署路径。

### 14.6 数据混合与采样

第一版建议从均衡任务 batch 开始，避免数量最大的 PointNav 数据淹没较难的行人跟随任务：

```text
person_follow : pointnav : imagegoal = 2 : 1 : 1
```

该比例只是初始值，应根据每个任务的有效样本数、梯度规模和验证集性能调整。每个 batch 内保留 task-balanced sampling，并分别记录各任务 loss 和成功率。

## 15. 统一初步方法

### 15.1 任务条件

在原有 target image 和 PointGoal token 之外增加一个小型 `Task Token`：

```text
person_follow | pointnav | imagegoal | objectnav
```

它用于消除“动态跟随”和“静态到达”的行为歧义。例如人物跟随通常保持距离，ImageGoal 则需要接近并停止；仅靠目标外观不一定能区分二者。
仅有 `Task Token` 仍不足以表达不同 benchmark 的到达定义。在其后增加一个 `Goal Specification Token`，显式编码：

```text
[task type, desired distance, tolerance/radius, terminal mode]
```

- Person Follow：给定期望跟随距离 `d_ref` 或安全距离带 `[d_min, d_max]`，`terminal mode = maintain`。
- PointNav：成功半径固定为 `r_success = 1.0 m`，`terminal mode = stop-on-arrival`。
- ImageGoal/Instance-ImageGoal：成功半径固定为 `r_success = 1.0 m`，并同时满足有效目标位置或正确实例约束，`terminal mode = goal-aware stop`。

本文所有 PointNav 和 ImageNav/Instance-ImageGoal 实验统一采用 `1.0 m` 成功半径，训练、验证和评测保持一致。`Goal Specification Token` 仍保留距离字段，以显式区分行人跟随的安全距离带与静态导航的到达半径，并方便后续迁移到其他协议。

### 15.2 共享与任务特定部分

共享：

- DINOv2-S/14 RGB encoder。
- History Context Cache。
- eVGGT-style frame/global Transformer。
- 统一8步 ego-centric waypoint head。
- action-conditioned forward dynamics 和 inverse dynamics训练框架。

通过 mask 区分的任务监督：

- Person Follow：目标相对位置、速度、可见性和保持距离。
- PointNav：goal-distance reduction、到达和 stop，不计算 identity loss。
- ImageGoal：实例匹配、目标可见性、目标相对位置、到达和 stop。
- 所有任务：waypoint、碰撞/free-space、future DINO/depth和inverse ego-motion。

### 15.3 静态与动态目标状态

目标状态 head/forward target 应带 `target_dynamic` 标记：

- 人物跟随：预测目标自身速度和未来相对状态。
- PointNav：目标世界位置静态，只更新 ego-relative goal；不计算目标自身速度预测。
- 静态 ImageGoal：预测目标相对位置和可见性，目标自身速度为无效项或固定为零。

避免把行人运动先验错误迁移到静态物体导航。

### 15.4 Stop 与短程 waypoint

统一 waypoint head之外增加轻量 `Stop Head`。训练目标来自到达半径、可见性和碰撞安全条件：

```text
h_t -> waypoint chunk
h_t -> stop probability
```

PointNav/ImageNav 必须具有明确 stop decision；行人跟随通常不输出永久 stop，而是根据目标停止和安全距离输出驻留/零速 waypoint。Stop loss按 `task_type` 做 mask。
三类任务的终止语义必须分开：

- Person Follow 是持续控制问题，优化对 `[d_min, d_max]` 的占用率和距离偏差；距离过近时后退，距离合适且目标暂停时输出零速 waypoint，但 episode 不因此成功终止。
- PointNav 是一次性到达问题；只有机器人进入 `r_success` 且显式输出 STOP 才记为成功。训练标签使用当前位置到目标的可通行测地距离（geodesic distance），不用可能穿墙的直线欧氏距离。
- ImageGoal 不能仅用“靠近某个坐标”判定成功；应在正确目标实例的有效 navigable viewpoint 附近输出 STOP，并满足 benchmark 对距离、实例匹配或可见性的定义。这可避免在同类错误实例旁停止也被计为成功。

对应的终止损失可写为任务条件化形式：

```text
L_terminal = L_follow_band                         (person_follow)
           | BCE(stop, inside_success_region)      (pointnav)
           | BCE(stop, valid_goal_viewpoint)       (imagegoal)
```

为减少成功边界附近的 STOP/继续抖动，推理时使用滞回阈值（进入阈值与退出阈值分开）或连续 `K` 帧确认；训练数据应专门采样成功边界内外的 hard negatives。

## 16. 对应评测 Benchmark

### 16.1 行人跟随：EVT-Bench

使用当前项目已有的 EVT-Bench 协议：

- STT：Static Target Tracking。
- DT：Dynamic Target Tracking。
- AT：Adversarial/Advanced Tracking，沿用仓库实际任务定义。

核心指标：

- Success Rate (SR)。
- Tracking Rate (TR)。
- Collision Rate (CR)。
- 目标距离误差、目标丢失后恢复率和平均无碰撞跟随时长。
- 多随机种子、不同 humanoid appearance 和不同场景的均值与方差。

### 16.2 PointNav：Habitat PointNav

优先使用 Habitat-Lab PointNav 协议，在 HM3D 或 MP3D/Gibson 的标准 train/val/test scene split 上评测，不能让同一场景同时出现在训练和测试中。

核心指标：

- Success。
- SPL。
- SoftSPL。
- Distance to Goal (DTG)。
- Collision count/rate。
- Path Length、oracle shortest-path length和终止准确率。

同时单独报告 easy/medium/hard geodesic-distance bins，以及目标是否初始可见。

本文将 PointNav 的 `success_distance` 固定为 `1.0 m`：机器人与目标点的 geodesic distance 不超过 `1.0 m` 且显式输出 STOP 时判定成功。训练、验证和评测使用完全一致的距离定义与 STOP 协议；报告 Habitat 结果时必须注明这是本文采用的 `1.0 m` 协议，若与某个官方 challenge 的默认阈值不同，不应直接横向比较数值。

### 16.3 ImageGoal：Habitat ImageNav / Instance-ImageGoal

优先采用 Habitat ImageNav 或与其兼容的 HM3D instance-image-goal episode协议。若现有数据只支持物体 crop实例导航，则建立严格的内部 Instance-ImageGoal benchmark，并明确与标准ImageNav的差异。

核心指标：

- Success。
- SPL / SoftSPL。
- Distance to Goal。
- Goal Recognition Success。
- Stop Accuracy。
- 初始不可见目标的 Search Success。
- 同类干扰实例下的 Correct Instance Rate。
- visible-target 与 initially-hidden-target 分组结果。

目标图像必须来自与起始视角不同的视角；测试场景、目标实例或至少目标外观组合需要与训练集隔离，以避免记忆目标图片。

本文将 ImageNav/Instance-ImageGoal 的成功半径同样固定为 `1.0 m`。标准 ImageNav 在有效 goal viewpoint/goal region 的 `1.0 m` geodesic 范围内显式 STOP 才成功；Instance-ImageGoal 还必须对应正确目标实例，不能在同类别错误实例附近停止。自建 benchmark 需公布距离度量、`1.0 m` 半径、有效观察角度/可见性、实例匹配规则和 STOP 要求；若官方 Habitat evaluator 的默认协议不同，需同时说明差异，不能直接混合比较。

### 16.4 跨任务统一报告

所有 benchmark 还应报告：

- 单一任务训练与多任务联合训练的差异。
- Person Follow、PointNav、ImageGoal 各自的性能，不只报告混合平均值。
- 参数量、显存、单步延迟和 history-cache 更新时间。
- 无 PointGoal、无 target image、模态冲突和定位噪声下的退化。
- 新场景、新人物/物体外观和摄像头扰动下的 OOD 表现。

## 17. 初步实施顺序

1. 复现原始 OmTrackVLA 行人跟随基线和 EVT-Bench 结果。
2. 实现 DINOv2-S + eVGGT-style RGB-only person-follow policy，不加辅助 dynamics。
3. 加入 PointNav 数据、Task Token、Stop Head和Habitat PointNav评测。
4. 加入 action-conditioned future DINO/depth辅助监督和inverse dynamics，逐项消融。
5. 先加入visible-target object-crop数据，验证通用目标实例匹配。
6. 再加入initially-hidden、跨房间和hard-negative数据，升级为完整Instance-ImageGoal/ImageNav。
7. 最后进行person-follow、PointNav和ImageGoal的task-balanced联合训练，并与各自单任务模型比较。

第一阶段论文主结果至少应覆盖 EVT-Bench + Habitat PointNav+ImageNav列为完整主任务。
