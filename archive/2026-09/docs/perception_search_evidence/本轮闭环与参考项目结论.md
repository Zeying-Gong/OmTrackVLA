# 本轮闭环验证与 LightNav 参考结论

本轮结果：**v4 不晋升为主模型；继续从原 Phase 2 推进感知监督和搜索控制。** 原验收范围仍为任意目标跟随、图像/坐标/混合三模式导航、主动搜索和重获、避障及 Thor 离线部署，尚未完成项目验收。

用户随后明确暂无实机硬件，当前只关注仿真并争取 SOTA。因此实机接入和 Thor 测量暂停，近期工作以 EVT-Bench 仿真为主：核对 TrackVLA、LightNav-0 等公开基线的任务条件、数据分割及计分协议，先建立可比基线，再验证感知、恢复搜索和训练改动。四例开发诊断或离线 ADE 改善均不能作为 SOTA 证据；原目标条件和部署输入边界继续保留。

## 已完成的训练与数据工作

四条长训练源自然结束，共 366 个动作步骤。按采集前冻结的 21 个锚点收集专家标签，19 条通过、2 条因 episode 提前结束失败；失败记录全部保留，没有替换样本。独立准入后共 23 条 train、4 条原有 val，物理场景隔离不变，val 路径与哈希不变。

v4 使用完整 reset→anchor 历史，逐次延续 GRU 与目标记忆，在真实末 4 次调用学习，不用填充凑序列。64 步训练完成；按原离线规则选中第 16 步，恢复 ADE 从 0.295181 m 降至 0.286103 m，约改善 3.1%。第 32/48/64 步未通过正常模式保留约束。冷启动 safe-stop 的预测轨迹误差不是执行位移，也不能代替已初始化后丢失的恢复能力。

## 固定四例闭环对比

在任何本轮闭环输出产生前固定三组协议：原 Phase 2、离线 best16、诊断 last64；每组同四例、同初始化、同配置和 runner，GPU 3 串行。四例实际分别运行 90、46、45、44 步，均自然结束；每组共 225 步，三组共 675 步。12 次运行均正常退出，没有漏计失败或换场景。

| 开发集结果 | 原 Phase 2 | v4 best16 | v4 last64（诊断） |
|---|---:|---:|---:|
| 成功 episode | 0/4 | 0/4 | 0/4 |
| 满足跟随判据的帧 | 21/225 | 22/225 | 20/225 |
| GT 目标丢失次数 | 5 | 5 | 5 |
| GT 再次可见次数 | 1 | 1 | 1 |
| 因视觉不确定停车的步骤 | 186 | 185 | 184 |
| 已检测到的旧返回帧 | 0 | 0 | 0 |

best16 只在 AT1700 多 1 个跟随帧，没有新增成功案例或 GT 再次可见事件。GT 再次可见不代表控制器确认了同一身份，更不代表主动搜索成功。各例 `human_collision` 记录为 0，也不能替代分别统计静态/动态碰撞的原验收要求。四例来自两个永久验证场景，属于开发诊断，不能估计完整项目的最终 SR。

因此继续增加单一恢复 waypoint 训练量没有得到闭环收益的支持。当前控制器在视觉置信不足且 UWB 缺失时将三轴动作清零；现恢复样本也没有可见性、可信 bbox 或候选身份监督。应同时补齐感知标签和状态控制，并分别验证“只改模型”“只改控制器”“二者一起改”的效果。

原始证据：`evidence_val4_v1/outputs/takeover/permanent_val4_closed_loop_v1/`。下载包 `takeover_val4_evidence_v1.tar.gz` 的 SHA-256 为 `c28cb50916c707367eb337cd9d237bd51ab9aa2c5bd17e47e8615d4ad9888a48`，134 个文件；其中清单所列 133 个文件均已逐项校验。图片、视频和权重留在远端，远端套件清单记录其哈希。

## LightNav-0 的采用方式

已审查固定 commit `c6f40e3220edbf7011e4f17eaf2c865416737d4d` 的 205 个文本文件，详见 [LightNav 审查](lightnav_reference/LIGHTNAV_REVIEW.md)。

- 借鉴请求序号与任务隔离、采集时刻里程计对齐、过期响应拒绝、Thor 离线环境配置及视觉缓存设计。
- 它的语言条件、10 个 SE(2) 空间路点，与我们指定目标/坐标条件和 8 个带秒偏移的 xy 路点不同，不能直接替换接口。
- 原库 MPC 主要做运动学轨迹跟踪，缺少通用障碍物约束，也缺少完整的轨迹采集年龄限制；需补强后再采用相关设计。
- 作者的 Thor 178 ms 是服务端中位数，不能作为我们完整采集到控制链路 ≤200 ms 的证明。
- 根代码 Apache-2.0 不覆盖所有适配代码、资产和权重；当前只读参考，没有导入不明许可的权重或第三方评测代码。

## 正在补齐的下一层

1. 独立搜索状态机已安装到 `omtrackvla/control/active_search_fsm.py`，实现原目标任务边界、输入时效、确认滞回、累计搜索预算和有期限的零平移偏航建议。审查又修正旧许可回放、处理延迟凑满确认时长、重复帧刷新目标记忆等边界；本机及远端 Python 3.9 均通过 50 项 CPU 测试。它仍需真实身份/运动许可来源和执行端 watchdog，不能称为已部署的主动搜索。
2. 已在固定四条 train 长源重放同一动作，采集 370 个同次渲染 RGB/panoptic 观测。独立验证器重新读取 740 个媒体文件、复算标签及 4,348 项对齐检查，全部通过；19 个原样本保持不变。645 次前缀比较包含重复，去重只有 228 个历史观测具有原像素和时间参照；其余 138 个非终末观测只核对原策略 RGB 统计及几何等，4 个终末观测没有下一策略 RGB 统计。不能把 370 帧全部称为原图逐像素复现。
3. 标签 loader `omtrackvla/data/perception_sidecar.py` 与独立 bbox/visibility 有效位已安装到远端。完整 19 条真实前缀均通过输入不变、标签对齐及原锚点轨迹监督检查；新标签只用于末四次真实调用，未知身份、停车、运动许可和绑定标签仍无效。相关 65 项不同的 CPU 测试通过：首次旧 v4 测试因 fixture 环境路径报错，设置已有 `OMTRACKVLA_REPOSITORY` 后仅重跑受影响模块通过，失败日志保留。采集器 47 项及独立验证器 19 项测试是另外的历史检查，未混入此 65 项计数。
4. 已用原 Phase2 权重在 GPU7 做真实 BF16 前向与反向：STT anchor027 完整 28 次调用、24 次预热、末四次标签 `[1,1,1,0]`，三个有效目标框。visibility 和 bbox 损失分别为 1.51743054、0.06158895，两个头均有有限非零梯度。没有构造优化器、更新或保存权重；父 checkpoint 哈希不变，loader 的显式 optimizer 入口仍拒绝使用。这证明监督接线有效，不代表定位精度或闭环成功率已经提高。CPU 和反向证据分别在 `perception_supervision_review/cpu.json`、`backward.json`。
5. 永久四例感知评估协议已冻结，分母为 229 个标签观测、225 次非终末预测；缺失/非法预测计入失败，不按预测置信度筛掉错误框。21 项 CPU 协议/指标/模拟回放测试通过，真实 val 采集与独立准入仍在实现；既有带绘制叠加的图像不能当作原始输入。补齐该验证数据后才开展感知优化器实验，再接身份校准与有界搜索仿真对照。不能把 FSM 的 rad/s 直接当成 Habitat 归一化 yaw；实测世界时间间隔有 0.048 和 0.056 秒，需要明确命令时间合同。三模式、非人物目标与场景规模继续保留，实机部分按用户要求暂停。
