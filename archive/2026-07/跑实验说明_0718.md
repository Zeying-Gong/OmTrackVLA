# OmTrackVLA 训练复现（2026-07-18）

## 目标与复现口径

目标是先按官方组件和全局 batch 复现 baseline，再做模型改进。官方
`ckpt_0401_text_model_epoch01_step439700.pt` 暴露的关键配置为：

```text
Qwen/Qwen3-0.6B
DINOv3 ViT-S/16 + SigLIP SO400M Patch14-384
history=31, n_waypoints=8, vision_feat_dim=1536
epochs=2, batch_size=8, lr=2e-5
weight_decay=0.01, grad_clip=1.0, BF16
alpha_task=[2,2,1], beta_nav=10, no_tanh_actions=true
distributed=false, final step=439700
```

需注意：checkpoint 记录的训练数据路径是 `0330/{stt,dt,at}_seed1000`，
当前拿到的归档是 `sim_data0420`。因此能复现模型、优化配置和近似闭环指标，
但不应期望数据量、loss 曲线和 439700 step 完全一致。

## 开发机执行：生成 frames 和 JSONL

本次已在开发机启动下列串联脚本：先用12个CPU worker完成数据转换，
成功后自动使用GPU 0生成视觉缓存。该脚本可以断点重跑：

```bash
cd /robot/robot-research-exp-0/user/gzy/OmTrackVLA
WORKERS_PER_TASK=4 GPU_LIST=0 BATCH_SIZE=8 bash run_dev_official_0420.sh
```

这一阶段主要使用 CPU、ffmpeg 和分布式存储，适合直接在开发机运行。
脚本默认每任务使用4个CPU shard（共12个ffmpeg进程）并行处理 STT/DT/AT，
分别写入 `frames/{stt,dt,at}` 和 `jsonl/{stt,dt,at}`：

```bash
cd /robot/robot-research-exp-0/user/gzy/OmTrackVLA
bash prepare_official_0420.sh
```

日志：

```bash
tail -f logs/prepare_official_0420/stt_shard0.log
tail -f logs/prepare_official_0420/dt_shard0.log
tail -f logs/prepare_official_0420/at_shard0.log
```

运行结束后检查：

```bash
find data/official_0420/jsonl -type f -name '*.jsonl' | wc -l
find data/official_0420/frames -type f -name '*.jpg' | wc -l
tail -n 10 logs/prepare_official_0420/{stt,dt,at}_shard*.log
```

`make_tracking_data.py` 已扩展为递归识别
`task/seed/pass/scene/episode/<id>_info.json`，并使用 namespace 防止三个任务的同名
scene/episode 覆盖。大数据默认只写 JSONL，不在内存中聚合百万样本的
`dataset.json`。

## 开发机执行：单 GPU 预计算视觉 token

必须在上一阶段完成后运行。本机单 GPU 命令：

```bash
cd /robot/robot-research-exp-0/user/gzy/OmTrackVLA
GPU_LIST=0 NNODES=1 NODE_RANK=0 BATCH_SIZE=8 \
  bash precache_official_0420.sh
```

日志：

```bash
tail -f logs/precache_official_0420/node0_shard0.log
```

脚本显式使用本地 DINOv3 ViT-S/16 和 SigLIP，开启 Hugging Face 离线模式，
真正按 `BATCH_SIZE` 批量编码。输出为每帧 4 个 coarse token 和 64 个 fine token，
以 FP16 `.pt` 保存。

缓存完成后检查：

```bash
find data/official_0420/vision_cache -type f -name '*_vcoarse.pt' | wc -l
find data/official_0420/vision_cache -type f -name '*_vfine.pt' | wc -l
```

coarse、fine 数量都应与 JPG 帧数一致。单 GPU 预计算可能耗时很长；
脚本可重跑并自动跳过已存在的 token。

严格保持全局 batch 8 时，推荐两机每机4卡（合计8卡），
而不是两机每机8卡。节点0：

```bash

MASTER_ADDR=<node0_ip> MASTER_PORT=29500 \

  bash train_official_0420.sh
```

节点1：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
NNODES=2 NODE_RANK=1 GPUS_PER_NODE=4 BATCH_PER_GPU=1 \
MASTER_ADDR=<node0_ip> MASTER_PORT=29500 \
OUT_DIR=/robot/robot-research-raw-data-0/user/gzy/omtrackvla_ckpts/repro_0420 \
  bash train_official_0420.sh
```

两个节点必须共享数据、视觉缓存和 checkpoint 目录，防火墙必须允许
node1 连接 node0 的 `MASTER_PORT`。脚本会检查
`NNODES * GPUS_PER_NODE * BATCH_PER_GPU == 8`，不符合时拒绝启动，避免无意改变官方全局 batch。

## 与官方完全一致时的剩余差异

1. 官方 checkpoint 使用 0330 数据，当前是 0420 归档。
2. checkpoint 是单 GPU、batch 8、`distributed=false`；8卡x1保持了全局 batch，
   但 DDP sampler 的 shuffle 顺序不会逐位一致。
3. checkpoint 含一个值为零的 `log_std` 参数，当前公开 deterministic waypoint
   trainer 不使用它，对当前 masked-MSE forward 无影响。
4. 最终结论必须用 EVT-Bench STT/DT/AT 闭环 SR/TR/CR 评估，不能只比较
   training loss。
