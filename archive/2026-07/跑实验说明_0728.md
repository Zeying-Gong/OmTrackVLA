# OmTrackVLA 实验说明（2026-07-28）

## 1. 目标

开发统一部署的人体导航与跟踪算法，支持三种目标输入模式：

- 纯视觉模式（ImageNav）：只提供目标 RGB 图像，通过检测、目标匹配和时序跟踪完成导航。
- 纯坐标模式（PointNav）：提供机器人坐标系下的目标方位，由 UWB 或人工选点获得。
- 混合模式：同时使用目标图像和目标方位，视觉负责身份判断，坐标负责空间定位。

仿真任务包括：

- STT：单目标跟踪，测试基础跟随能力。
- DT：输入目标 RGB 图像，在外观不同的干扰人物中匹配并持续跟踪目标。
- AT：目标与干扰人物外观相同，需要依据“第一个看到的人”等时序条件绑定目标。

## 2. 当前 Oracle 的含义

当前 `OraclePerception` 直接使用 Habitat 提供的目标 semantic ID、panoptic mask、机器人真实位姿和目标真实位姿，输出：

- 目标是否可见；
- bbox 和 footpoint；
- 机器人坐标系下的目标相对位置；
- 距离、方位角和 mask 面积。

因此，当前 STT、DT、AT oracle 结果主要评估跟随控制，而没有真正评估检测、目标图像匹配、ReID 和目标关联。特别是 DT/AT 的目标身份已经由 semantic ID 直接给定。

当前结果应称为 `privileged-information Oracle Reference`，不能称为严格的数学理论上限。感知是 GT，但 v5/v6 控制器仍是人工启发式策略，并非最优控制。

## 4. 指标定义

- SR（Success Rate）：episode 结束时是否满足成功条件。
- TR（Tracking Rate）：整个 episode 中满足跟随条件的步数比例。
- Collision：发生人体碰撞的 episode 比例。
- Finish：正常结束比例。当前实现中基本等于 `1 - Collision`。

当前 `human_following` 要求目标距离不超过 3 m 且目标满足 facing/可见性条件。终局 success 还要求距离处于 1--3 m，并满足 episode 结束时的跟随判定。

注意：SR 偏重终局状态，不能代替全过程 TR。正式报告还需要补充 target identity accuracy、ID switch 和重捕获率。

## 6. 当前 V5 结果的实验口径问题

`REQUIRE_100_SUCCESS=1` 会让失败 episode 最多重新运行 5 次，并在重试时翻转避让方向。新的结果会覆盖旧结果。因此当前持久化汇总混合了 first-attempt 和 best-of-5 结果，不是严格的单次成功率。

后续正式实验必须同时报告：

- first-attempt SR/TR/Collision（主要指标）；
- best-of-N success（仅表示失败恢复能力）；
- 重试次数分布。

不同控制器和配置必须使用独立 `OUTPUT_ROOT`，不能复用同一目录后依赖 resume/覆盖结果。

## 7. V5 与 V6 的策略差异

v6 复用 v5 的 `OracleNavmeshFollower`，主要修改以下策略：

| 策略 | v5 | v6 |
|---|---:|---:|
| 正常跟踪距离 | 1.5 m | 1.3 m |
| 优先保持视觉 | 关闭 | 开启 |
| 来人安全退避 | 关闭 | 目标进入 2.2 m 时启用 |
| 紧急退避 | 关闭 | 小于 0.85 m 时启用 |
| mask 过大处理 | 无 | 超过画面 30% 时拉开 |
| 低可见重构图 | 无 | 连续 8 步后侧向调整 |
| 坐标接管最低速度比例 | 0.1 | 0.5 |
| 迎面运动记忆 | 4 步 | 6 步 |
| 侧向避让触发距离 | 2.0 m | 2.2 m |

可以概括为：v5 规则较简单、整体更稳定；v6 更积极处理迎面目标、过近、低可见和暂时丢失，但也可能引入新碰撞或控制振荡。

## 8. Oracle、模块化方法和 Learning-based 方法的关系

模块化与 learning-based 不是互斥概念。模块化系统也可以包含 learned detector、learned ReID 和 learned controller；端到端只是另一种架构选择。

当前 v5/v6 可以被超过，因为它们只是 `GT 感知 + 启发式控制`。超过 v5/v6 表示控制策略优于当前 Oracle Reference，不等于超过真正的理论最优。

更合理的参考层次是：

```text
GT 感知 + v5/v6 控制       当前 Oracle Reference
GT 感知 + 最强 Learned 控制 更强的 privileged reference
真实感知 + 最强控制         最终可部署系统
```

理想情况下，最终系统可以超过 `GT 感知 + v5`，因为 learned controller 或更好的 MPC 可以弥补感知误差并超过 v5 的启发式控制。但真实感知系统通常不应稳定超过 `GT 感知 + 同一个最强控制器`；若超过，需要检查随机性、数据泄漏和指标利用。

单纯 Behavior Cloning 主要用于逼近 teacher，不能指望稳定超过 v5。要超过 v5，需要更好的规划器、residual learning、DAgger、RL，或者直接优化 TR/Collision 的学习目标。

## 9. 2x2 核心消融

先通过独立 A/B 选择并冻结一个 controller 版本，然后执行：

| 感知 | 控制 | 记号 | 实验目的 |
|---|---|---|---|
| GT 感知 | 固定 v5/v6 | R00 | Oracle Reference |
| 真实感知 | 同一固定控制器 | R10 | 测量感知差距 |
| GT 感知 | Learned Control | R01 | 测量控制提升/差距 |
| 真实感知 | Learned Control | R11 | 最终系统 |

分析方式：

```text
感知损失 = R00 - R10
控制收益 = R01 - R00
部署损失 = R01 - R11
最终收益 = R11 - R00
```

上述差值应分别对 SR、TR、Collision、身份正确率计算。由于 Collision 是越低越好，报告时需要注意符号方向。

这套消融需要分别在纯视觉、纯坐标和混合模式执行。当前 oracle 同时使用 GT mask 和精确坐标，更接近特权混合模式；后续需要构建遵守输入约束的 mode-specific reference：

- 纯视觉 reference 禁止控制器读取目标真实坐标；
- 纯坐标 reference 禁止控制器读取 mask/可见性；
- 混合 reference 才允许同时使用两类信息。

## 10. 下一阶段执行顺序

### 阶段 A：冻结协议和 Oracle Reference

1. 统一 train/val metric 配置。
2. 以 first-attempt 为主指标，固定 seed。
3. 补齐或明确排除 `DT/val index 186`。
4. 在无偏 val 集上完成 v5/v6 配对 A/B。
5. 冻结一个控制器版本，后续感知实验不再修改控制器。

### 阶段 B：真实感知 + 固定控制器

第一版模块化 baseline：

```text
目标图像/坐标
        -> Person Detection / Segmentation
        -> 目标图像匹配或 first-visible 绑定
        -> ByteTrack / BoT-SORT + ReID
        -> RGB-D/单目深度相对位置估计
        -> TargetObservation
        -> 冻结的 v5/v6 Controller
```

需要额外评估：

- detection recall；
- target selection accuracy；
- IDF1、ID switch；
- 相对位置 RMSE；
- visibility recall；
- target reacquisition rate；
- SR、TR、Collision。

STT、DT、AT 的目标初始化逻辑应显式区分：

- STT：检测到目标人物后锁定；
- DT：用目标 RGB crop 对候选人物做外观匹配；
- AT：第一次满足可见条件时绑定 track ID，之后禁止按外观重新初始化。

### 阶段 C：收集 Learned Control 数据

现有全量 v5 JSON 不包含足够的逐 step 监督。需要重新采集代表性子集，启用 `--save-steps`，并建议记录：

- RGB、depth、target mask/bbox；
- `relative_xy`、目标速度、可见性和置信度；
- robot state、局部障碍信息；
- controller mode、waypoint、oracle action；
- collision/following reward。

先采集有代表性的子集完成 pipeline，不需要立即重跑全部 25,985 个 episode。

### 阶段 D：Learned Control

推荐优先预测 local waypoint 或 desired velocity，而不是直接端到端输出底盘动作：

```text
TargetBelief + local map + temporal history
                    -> Learned waypoint / desired velocity
                    -> safety controller
```

训练顺序：

1. Behavior Cloning 模仿 v5/v6；
2. DAgger 补充模型偏离后的状态；
3. residual policy：`action = base_controller_action + learned_residual`；
4. 必要时使用 RL 直接优化 TR、Collision 和终局成功。

### 阶段 E：最终系统

依次实现目标：

```text
Real Perception + 固定控制器 接近 GT Perception + 固定控制器
GT Perception + Learned Control 超过当前 v5/v6 Reference
Real Perception + Learned Control 超过当前 v5/v6 Reference
Real + Learned 接近 GT + Learned
```

## 11. 正式实验最低要求

- 开发集调参，独立 val/test 做最终比较；
- 同一批 episode、相同 seed、相同输入约束；
- 不使用 best-of-5 作为主要结果；
- 每个实验使用独立输出目录；
- 同时报告 SR、TR、Collision、身份正确率；
- 对初始 step 已碰撞的 episode 单独标记并分析；
- 保存逐 episode CSV，支持 paired comparison 和 bootstrap 置信区间；
- 记录代码版本、controller version、配置和模型 checkpoint。

## 12. 当前结论

1. v5 全量结果可作为临时 Oracle Reference，但不是严格 first-attempt 上限。
2. v6 修复部分 v5 失败，同时存在回归，需完成无偏配对评测。
3. 下一项最高优先级工作是实现 `真实感知 + 冻结 v5`，建立第一个可部署模块化 baseline。
4. 之后再采集逐 step oracle 数据，训练 learned/residual controller。
5. 最终系统有可能超过当前 v5/v6 reference，但真正应该逼近的是 `GT 感知 + 最强控制器`。

## 13. RGB 感知 + V5 Oracle Control 初版（2026-07-28）

已实现第一版 `真实感知 + v5 控制` STT baseline。新增文件：

- `rgb_person_perception.py`；

- `eval_oracle_indices_8gpu.sh` 和 `eval_oracle_modular_8gpu.sh` 的 `PERCEPTION` 参数。

感知链路为：

```text
当前 RGB
  -> Faster R-CNN MobileNetV3 COCO person detector
  -> 首次可见目标初始化
  -> bbox IoU + HSV histogram + 中心距离短时关联
  -> bbox torso 区域 RGB-D 中值深度
  -> 相对 (forward, left)、range、bearing
  -> TargetObservation
  -> v5 OracleNavmeshFollower
```

非 oracle 感知模块不读取 panoptic、目标 semantic ID 或目标/机器人真实位姿。v5 控制器仍读取目标 agent 真值位置和 navmesh，这是本消融中保留的 privileged Oracle Control。

Torch CUDA detector 与 Habitat EGL 同进程会导致黑色 jaw RGB。即使使用独立 detector worker，当前 GPU 0 的 EGL 路径仍出现黑帧/native abort。Xvfb 后端可以稳定产生 RGB，因此本轮有效 smoke 使用：

OUTPUT_ROOT=/tmp/rgb_person_v5_stt_val0_xvfb \
LOG_ROOT=/tmp/rgb_person_v5_stt_val0_xvfb_logs \
RENDER_BACKEND=xvfb SAVE_STEPS=1 \

4. 在单 GPU 上顺序跑至少 20--100 个 STT/val episode；
5. 完成 learned ReID 后再测试 DT；
6. 实现“first visible track ID”绑定后再测试 AT；
7. 批量运行前修复 detector GPU 可见性预检，并决定 Xvfb 或双 GPU EGL 部署方式。

## 14. 无文本 DT/AT Smoke（2026-07-28）

任务输入定义已进一步明确，算法不读取数据集 instruction：

- STT：场景中只有目标人物，检测后直接跟踪；

2. 使用 ByteTrack/BoT-SORT 的轨迹状态和速度预测；
3. 遮挡时保持目标 track 为 lost，禁止直接切换到重叠干扰框；
4. 重捕获时联合 goal crop 相似度、轨迹预测和时间一致性；
5. 先在 10--20 个含交叉/遮挡的 DT episode 上验证 identity precision，再决定全量。

## 15. OSNet ReID 与遮挡状态机回归（2026-07-29）

为修复 DT/val index 0 在人物交叉时的 ID switch，未采用带 AGPL 约束的 BoxMOT，改为引入 MIT 许可的 `torchreid` OSNet-x0.25：

- 代码：`third_party/torchreid/`；
- 权重：`models/reid/osnet_x0_25_msmt17.pt`；
- 权重 SHA256：`6f57607fed9f502b9efed546108132ee715df5a5b6e6932c6269bacb47f59f99`；
- 感知版本：`rgb-person-mobilenet-osnet-v4`。

当前关联器联合固定 goal crop embedding、在线 track embedding、HSV、bbox 速度、中心距离和尺度一致性。目标图像模板不再被在线检测结果更新；近处行人产生突然放大的合并框时，将目标置为 lost 而不是切换身份；重新关联时使用更严格的 goal ReID 阈值。整个流程不读取 instruction 或文本描述。

### 15.1 DT/val index 0 关联改进

同一个 deterministic episode 的对比如下：

| Variant | SR | TR | Collision | Detection | Target precision | Target recall | Mean target IoU |
|---|---:|---:|---:|---:|---:|---:|---:|
| DINOv3/旧关联 | 0% | 26.67% | 100% | 81.67% | 16.33% | 20.51% | 0.149 |
| OSNet + 保守遮挡门控 | 0% | 32.26% | 0% | 25.81% | 100% | 34.04% | 0.836 |
| OSNet + 丢失后严格 ReID | 0% | 71.43% | 100% | 62.50% | 100% | 68.63% | 0.821 |

原始错误发生在第 3 步：远处目标被近处干扰者遮挡，detector 只输出一个大框，旧关联器接收该框并污染在线模板，第 7 步两人分开后持续跟错。新状态机在两次交叉后均恢复到正确目标，严格版本的 identity precision 为 100%。

严格版本最终仍在第 56 步碰撞。第 50 步开始 detector 无输出，但目标仍在 GT 视野附近；v5 进入 `approach_coordinate`，路径 waypoint 使用 privileged GT target position，而速度缩放继续使用真实感知最后一次保存的旧 `range_m`。机器人从 1.79 m 连续接近到 0.35 m 后碰撞。这是不可见状态下感知/控制接口不一致，不是新的 ID switch。

### 15.2 AT/val index 0 当前版本回归

|---:|---:|---:|---:|---:|---:|---:|
| 0% | 73.77% | 100% | 50.82% | 100% | 51.67% | 0.846 |

AT 同样没有换人，但检测丢失后发生 `approach_coordinate` 碰撞，终止距离为 0.38 m。旧 DINOv3 版本在该 episode 上成功，不代表新 ReID 退化为错人；当前逐步指标显示是更保守的遮挡门控降低 recall，并暴露了相同的不可见状态控制问题。

## 16. 可用 RGB Baseline 冻结（2026-07-30）

baseline 的目标不是把碰撞率强行压到 0，而是在统一部署形态下优先获得可用 SR/TR，同时要求身份选择可靠、碰撞不是多数。低碰撞 `stop-search` 版本保留为 safety ablation，不作为主 baseline。

### 16.1 冻结配置

```text
Perception: Faster R-CNN MobileNetV3 person proposals
Detector threshold: 0.30
Identity: OSNet-x0.25 + fixed HSV goal template + temporal bbox state
Controller: v5 coordinate policy
Renderer: Xvfb
STT initialization: first-visible
DT initialization: goal-crop
AT initialization: first-visible
Text grounding: disabled
```

`PERSON_SCORE_THRESHOLD=0.10` 会把 DT/val 0 的 identity precision 从 100% 降到 52.5%，因此不采用；`0.30` 在同一 episode 上把 target recall 从 25.81% 提升到 67.44%，同时保持 identity precision 100%。

脚本默认值已经改为 `PERSON_SCORE_THRESHOLD=0.30`。`LOST_TARGET_POLICY=auto` 解析为 `coordinate`；需要低碰撞消融时显式设置 `LOST_TARGET_POLICY=stop-search`。

### 16.2 Val 0--3 小批量结果

| DT | 4 | 50.00% | 71.43% | 25.00% | 75.00% | 100% | 72.37% |
| AT | 4 | 25.00% | 64.37% | 25.00% | 75.00% | 100% | 44.28% |

12 个 episode 的 identity precision 均为 100%。每个任务只有一个碰撞 episode，碰撞不是多数；DT 已有两个成功 episode，其中 DT/val 1 为 TR 100%，DT/val 2 为 TR 95.67%。这组结果足以作为第一版真实感知 baseline，但样本量不足以作为最终论文结果。

## 17. RGB Baseline Val-20 结果（2026-07-31）

使用第 16 节冻结配置，对 STT、DT、AT 分别运行 val dataset indices 0--19，共 60 个 episode。所有 episode 均保存视频和逐 step 候选诊断，最终无 Python 评测错误。DT 四路并发时 index 14 出现一次无 traceback 的 native 中断，之后以两路并发仅补跑缺失 indices，未重跑已有结果。
