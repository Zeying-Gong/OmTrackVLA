# OmTrackVLA oracle 全量评测接续说明（2026-07-25）

本文档记录 2026-07-25 对 modular oracle 全量评测 launcher 和 controller 的修复、开发机单 GPU 回归结果，以及集群 8 GPU 正式运行方法。后续接手的 AI 应先阅读本文，再阅读 `模块化行人跟随接续说明_0724.md`，不要重新使用 controller version 3 的结果或旧 launcher 行为。

## 1. 当前结论

- 当前批量结果版本是 **controller version 4**。
- `oracle_modular_batch.py` 写入 `controller_version: 4`。
- `summarize_oracle_modular.py` 只统计 version 4；version 3 和更旧 JSON 显示为 `stale`。
- 正式输出目录保持不变：

```text

```

- 仓库软链接：

```text

```

- 直接重新执行全量命令会断点续跑。只有当前 controller version 的完整 JSON 和非空 MP4 会被跳过；旧 v3 结果会自动覆盖。
- `RUN_ID` 只控制日志目录名，不控制结果版本，也不隔离正式输出目录。

## 2. 8 GPU launcher 中断问题

旧运行 `oracle_v3_full_20260725_172213` 只生成 98 个 STT-train 结果后停止。根因不是 GPU 故障：单个 worker 每完成一个 scene 后以退出码 `75` 请求重启，旧 launcher 把 `75` 当作失败并退出。

当前 `eval_oracle_modular_8gpu.sh` 已修复：

- 默认使用 EGL；
- 每个进程最多处理一个 scene，释放 Habitat/native 资源后重启；
- 将退出码 `75` 识别为正常的 scene batch 完成并继续 pending scenes；
- 原生崩溃最多连续重试 3 次；
- episode JSON/MP4 按条目持久化，launcher 或 worker 中断后可以续跑；
- 最终才执行 `REQUIRE_100_SUCCESS=1` 检查。

正常 shard 日志应反复出现：

```text
[oracle-worker] scene batch complete; restarting for pending scenes
[oracle-worker] attempt=2 ...
```

旧 GLX/Xvfb 运行曾出现：

```text
Assertion frameBuffer_[cubeSideIndex].checkStatus(...) failed
.../CubeMap.cpp:311
```

正式运行保持 `RENDER_BACKEND=egl`（当前默认值），不要切回旧 GLX 路径。

## 4. controller version 4 修复

最终修改位于 `oracle_modular_follow.py`，主要行为如下：

1. 启动追赶采用 `0.25/step` 平移 slew limit；人物尚未移动时最大追赶动作限制为 `0.65`，避免初始阶段冲入人物运动路径。
2. 3 m 内 incoming 人物使用“切向人物速度前馈 + 径向距离反馈”。incoming 时目标距离为 1.5 m，人物通过或停止后收敛回 1.2 m。
3. incoming 持续时周期性进入 `yield_pass`，平滑停车让人物通过；距离低于 0.8 m 时退出让行并恢复紧急距离控制。
4. 目标被门框等遮挡时继续使用 oracle 坐标和 navmesh 恢复视角，不再在旧的 `hold_coordinate` 状态原地等待。
5. 正常终态收敛到官方成功距离 `[1.2, 1.5] m`，同时满足像素/facing 条件。

不要恢复开发过程中失败的策略：

- incoming 长期固定半速或全速倒退；
- 沿 retreat waypoint 一直逃跑；
- 卡住后直接发纯 lateral 逃逸。

这些策略都在开发机真实 Habitat 回归中失败，表现为人物持续追赶、机器人退入死路或 lateral 横穿人物轨迹。

## 6. 集群 8 GPU 正式全量命令

在实际分配了 8 张 GPU 的集群节点运行：

```bash
cd /robot/robot-research-exp-0/user/gzy/OmTrackVLA

RUN_ID=oracle_v4_full_$(date +%Y%m%d_%H%M%S) \
GPU_LIST=0,1,2,3,4,5,6,7 \
NUM_SHARDS=8 \
TASKS=stt,dt,at \
SPLITS=train,val \
SAVE_VIDEO=1 \
VIDEO_FPS=8 \
RENDER_BACKEND=egl \
REQUIRE_100_SUCCESS=1 \
bash eval_oracle_modular_8gpu.sh
```

用户原命令中的 `RUN_ID=oracle_v3_full_*` 技术上也能运行，因为 `RUN_ID` 只命名日志；但必须使用 `oracle_v4_full_*`，避免人或 AI 将新日志误认为 version 3 结果。

建议在集群任务调度器、`tmux` 或其他持久 session 内运行，避免 SSH 断开终止 launcher。同一正式输出目录不要同时启动两套全量任务。
