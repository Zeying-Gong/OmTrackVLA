# 模块化行人跟随接续说明（2026-07-24）

本文档用于后续 AI/开发者直接接手当前工作，记录已经确定的算法目标、现有实现、数据映射、运行命令、实验结果、已知问题和下一步任务。

## 1. 当前最终决策

当前优先实现模块化行人跟随系统：

```text
目标感知前端
  ↓
TargetObservation
  ↓
局部路径/控制后端
  ↓
[forward, lateral, yaw] 连续动作
```

当前主版本 **保留 lateral**，原因如下：

- Habitat 当前使用 Spot/全向动作接口，支持侧向移动；
- OmTrackVLA 原始训练数据确实使用 lateral；
- 同一 episode 消融中，有 lateral 的 Tracking Rate 为 80.62%，无 lateral 为 72.87%；
- 人物快速横穿和暂时出画时，lateral 明显缩短重新捕获时间。

后续若部署到差速轮式底盘，不应直接删除训练策略的 lateral 输出。应保留统一二维 waypoint/轨迹表示，在机器人适配层将其转换为 `[linear, yaw]`。

## 2. 原始算法需求

系统需要支持三种目标输入模式：

1. **纯视觉模式**：第一帧目标行人可见，输入目标 RGB/crop；检测、ReID 和跟踪持续确定目标位置。
2. **纯坐标模式**：输入以机器人为原点的目标相对方位/距离，例如 UWB 或人工指定坐标。
3. **混合模式**：目标图像与相对坐标同时输入；坐标提供粗定位和遮挡接管，视觉确认身份和精确位置。

任务不是传统 ImageNav 的“在未知场景寻找目标图片对应地点”，而是：

```text
第一帧看到指定行人
→ 行人开始移动
→ 机器人持续跟随
→ 目标可能短时遮挡或离开视野
→ 预测/坐标接管/重新捕获
```

推荐的统一目标表示：

```text
Pixel Goal / bbox 下边缘中心
range
relative_xy = [forward, left]
visible
confidence
target velocity
modality mask
```


单测：


当前 pipeline：

```text
Habitat RGB + panoptic + 目标 semantic ID
→ OraclePerception
→ bbox、bbox 下边缘中心、真值距离/方位
→ OracleNavmeshFollower
→ 每步重算 navmesh 最短路径方向
→ [forward, lateral, yaw]
→ Habitat agent_1_base_velocity
```

### 3.1 Oracle 感知

目标实例 ID 来自：

```python
episode.info["main_human_semantic_id"]
```

通过 Habitat panoptic 图中等于该 ID 的像素得到 oracle mask 和 bbox。脚点使用：

```text
u = (bbox_x1 + bbox_x2) / 2
v = bbox_y2
```

即 bbox 下边缘中心。不要恢复成 segmentation 最底部像素中位数；真实检测器通常只稳定提供 bbox，没有必要依赖过细的 mask 几何。

### 3.2 Oracle 控制

安全距离带当前为：

```text
min_distance = 1.2 m
max_distance = 1.5 m
```

控制状态：

- `approach`：距离大于 1.5 m，沿 navmesh 最短路径接近；
- `hold`：距离位于 1.2~1.5 m，只转向目标；
- `retreat`：距离小于 1.2 m，在 navmesh 上搜索能增加目标间距的安全撤离点；
- `*_coordinate`：视觉不可见，但 oracle/坐标模式仍有目标位置，继续沿 navmesh 跟随和转向。

曾经存在一个错误：`visible=false` 时 oracle 控制器直接停车，导致人物出画后永久跟丢。已经修复为坐标接管。后续实现纯视觉模式时，不能无条件使用真值坐标；应根据 `modality_mask` 选择短时预测、搜索或坐标接管。

## 4. 动作格式和速度

OmTrackVLA 与当前 oracle 使用相同格式：

```text
[forward, lateral, yaw]
```

三维输入在 Habitat 中都会先裁剪到 `[-1,1]`。配置路径：

```text
habitat-lab/habitat/config/benchmark/nav/track/track_train_stt.yaml
```

配置缩放：

```yaml
longitudinal_lin_speed: 15.0
lateral_lin_speed: 10.0
ang_speed: 6.28
ctrl_freq: 40
```

当前 oracle 默认允许三维完整上限：

```text
max_forward = 1.0
max_lateral = 1.0
max_yaw = 1.0
```

“上限相同”不代表后续学习策略应始终输出饱和值。真实部署需要按路径曲率、障碍距离、目标距离和控制周期重新标定。

OmTrackVLA 在 `trained_agent.py` 中把预测 waypoint 除以 `dt=0.1` 得到 `[vx,vy,wz]`，然后由 Habitat action 层裁剪。原始 episode 4 共 136 步，其中 lateral 非零 124 步，lateral 绝对值均值 0.0448、最大 0.1885。

## 7. EVT-Bench 指标定义

官方每步 `human_following` 条件：

```text
robot-human Euclidean distance <= 3.0 m
目标 panoptic mask pixel count > 10000
目标 mask fraction < 30% of image
```

最终 success 距离带：

```text
1.0 m <= distance <= 3.0 m
```

人与机器人碰撞：

```text
distance < 0.5 m
```

Tracking Rate：

```text
following_step / total_step
```

注意：清晰可见的远处 bbox 也可能因为 mask 小于 10000 像素而被记为 `human_following=0`。不要把 TR 的每次丢失都直接解释为检测失败。

## 10. 下一步任务

按优先级执行：

### P0：扩大 oracle 回归集

1. 不再只测试单个 episode；从 STT train/val 选择至少 10 个可复现 episode。
2. 增加 DT、AT 各至少 10 个 episode。
3. 每个 episode 保存相同 summary JSON 和视频抽样。
4. 与原始 `{episode}.json` 比较 SR/TR/CR、距离和步数。
5. 建立批量汇总脚本，并设回归阈值，例如 TR 不低于原始超过 3~5 个百分点。

在批量运行前先解决或确认 Xvfb 使用 llvmpipe 的性能问题。

### P1：替换感知前端

按以下顺序替换 oracle 感知，控制器暂时保持 oracle：

1. oracle bbox + oracle relative pose；
2. 预训练 person detector bbox + oracle target ID/坐标；
3. detector + tracker，第一帧 oracle bbox 初始化；
4. detector + tracker + ReID，支持遮挡后身份恢复；
5. 首帧 target crop 初始化，去除 oracle target ID。

评测时必须分别记录：检测可见率、身份切换、重捕获时间、TR、CR。

候选模块可以是 YOLO/RT-DETR + ByteTrack/BoT-SORT/StrongSORT。目标 crop 使用保持比例 resize + letterbox，不直接要求与当前 RGB 同尺寸。

### P2：实现三种输入 adapter

- Visual adapter：target crop → detector/ReID/tracker → bbox footpoint；
- Coordinate adapter：relative `(forward,left,range)` → 当前目标状态和视野外方向；
- Hybrid adapter：坐标缩小 ROI，视觉确认身份；视觉不可见时坐标接管。

统一输出 `TargetObservation`，不要让控制器分别维护三套逻辑。

### P3：深度策略

开发/对照阶段使用 Habitat oracle depth 或目标真值距离。RGB-only 部署可使用 Depth Anything V2，但其单目输出不能直接假设为稳定米制深度，需要尺度校准、时序滤波和置信度。

已有 checkpoint：

```text
/robot/robot-research-exp-0/user/gzy/InternNav/checkpoints/depth_anything_v2_vits.pth
```

第一版也可用 bbox 高度估计粗距离，但最终需要深度/UWB/尺度校准才能稳定保持实际距离。

### P4：生成训练数据

Replay 现有 STT/DT/AT episode，导出对齐字段：

```text
RGB history
target crop / target ID
bbox / mask / bbox footpoint
visible / occluded
relative_xy / range
robot pose / target pose
oracle local path / future trajectory
[forward,lateral,yaw]
collision / human_following
modality mask
```

从同一个 episode 派生 Visual-only、Coordinate-only、Hybrid 三种样本，保证目标和轨迹标签一致。不要简单拼接互不对应的 PointNav 和 ImageNav 数据。

### P5：学习控制器

先保持模块化：感知输出统一目标状态，学习控制后端输出局部轨迹或连续动作。推荐顺序：

```text
Behavior Cloning
→ 扰动/恢复数据
→ DAgger
→ 动态行人交互式 RL
```

NavDP 可以作为后续局部规划初始化或对照，但不是原始三模态算法的定义，也不是当前 P0/P1 的阻塞项。

## 11. 接手时不要重复踩的坑

1. 不要使用 `match-index=0` 与 0420 的 `4.mp4` 做指标对比。
2. 不要把 bbox 脚点改回依赖精细 mask 底部像素的实现。
3. 不要在视觉不可见时让混合/oracle 模式停车；坐标应接管。
4. 不要把 `mask < 10000` 导致的 `human_following=0` 一律算成检测失败。
5. 不要直接把 lateral 置零后宣称差速版本等价；需要动作投影和重新训练。
6. 不要误导入另一份 habitat-lab；必须设置本文档给出的 PYTHONPATH。
7. 不要以历史中断目录的结果替代 `oracle_modular_follow_full_v2`。

当前稳定架构是：**oracle bbox/目标坐标 + navmesh follower + 三维连续动作（含 lateral）**。批量结果必须使用 controller version 4；旧版本 JSON 会被视为 stale 并自动重跑。

## 13. 迎面行人碰撞修复（controller version 3）

全量初次运行在前 98 个 STT-train episode 中出现 17.35% 碰撞。代表性失败：

```text
dataset_index=5872
scene=53jtKd53a1X
episode_id=38
旧最小距离=0.472 m
旧结果=Collision / Success=0
```

根因不是 navmesh 不可达，而是动态避让逻辑错误：

1. 人物迎面走来时，控制器仍把人物当前位置当作导航终点并满速接近；
2. 进入 `retreat` 后，安全 waypoint 位于机器人后方，但旧控制器禁止负 forward，只原地旋转；
3. 行人继续前进，最终主动撞上静止/旋转中的机器人。

version 3 修复：

- 估计目标逐步世界位移在 robot-target 连线方向上的分量；
- 行人朝机器人移动且距离小于 3 m 时进入 `yield_incoming`，停止前进；
- 距离小于 2 m 时进入 `retreat_incoming`；
- retreat 允许负 forward，沿经过 navmesh 验证的安全 waypoint 倒退，同时保持朝向目标；
- 接近 1.2 m 安全边界时按距离误差降低速度，不再始终饱和；
- 目标可见但 mask 小于官方 10000 像素时进入 `approach_visibility`，缓慢靠近直到满足官方 facing，解决“距离合法但最终 success=0”。

index 5872 修复后：

```text
Success=1
Collision=0
TR=58.20%
steps=189
min_distance=1.355 m
end_distance=1.392 m
```

旧的 16 个碰撞 JSON 已全部定点重跑，修复后均 `Collision=0`。version 3 额外回归：

| dataset index | 用途 | Success | Collision | min distance |
|---:|---|---:|---:|---:|
| 5872 | 用户指出的迎面碰撞 | 1 | 0 | 1.355 m |
| 1809 | 另一迎面碰撞 | 1 | 0 | 1.155 m |
| 6898 | 初始距离很近 | 1 | 0 | 1.129 m |
| 6900 | 最终 mask 太小导致失败 | 1 | 0 | 1.256 m |

batch JSON 现在包含：


`summarize_oracle_modular.py` 只统计当前 controller version。缺少版本号或旧版本结果显示为 `stale`，不进入 SR/TR/CR。`eval_oracle_modular_8gpu.sh` 断点续跑时也只跳过当前版本的完整 JSON+MP4，所以重新执行全量命令会自动覆盖所有旧结果。

## 14. 离散目标运动与遮挡恢复修复（controller version 4）

version 3 首批 98 个 STT-train episode 中剩余 3 个失败：2455、6361、6954。与 `sim_data0420/stt_train_oracle/seed_1000/pass1` 的成功轨迹对齐后，确认了三个控制问题：

- 人物动画的位置会隔帧更新，单帧速度判定使 `retreat_incoming` 与 `approach/yield` 振荡；
- 目标被门框遮挡且距离位于旧的 1.2--1.5 m 静止带时，`hold_coordinate` 无法恢复官方 `facing`；
- incoming 只按当前距离触发，快速接近的人物会在退避生效前把机器人逼入家具或墙边。

version 4 的最终控制逻辑：

- 启动追赶使用 0.25/step 的平移 slew limit，人物尚未移动时最大追赶动作限制为 0.65，避免初始阶段冲到人物运动路径中；
- 3 m 内 incoming 人物使用“切向人物速度前馈 + 径向距离反馈”，incoming 时目标距离为 1.5 m，人物通过或停止后收敛回 1.2 m；
- incoming 持续时周期性进入 `yield_pass`，在安全距离内平滑停车让人物通过，低于 0.8 m 时立即恢复距离控制；
- 不可见时继续使用目标坐标和 navmesh 恢复视角，不再进入 `hold_coordinate`；
- 静止带收紧到 1.2 m 附近，终态满足官方距离和像素阈值。
