### 目标来源定义

原 B 的 `OracleNavmeshFollower` 不仅在目标可见时使用视觉观测，还会在路径规划和目标丢失时
读取 `target_agent` 的 GT 世界坐标。因此原 B 不是纯视觉实验，而是带特权坐标接管的
`B-hybrid` 混合模式上限。

- `B-visual`：目标可见时只能使用 RGB/ReID 估计的局部目标点；目标丢失后 stop/search，
  禁止读取 `target_agent` 坐标。Oracle navmesh 只能用于绕障路径，不得提供目标位置。
- `B-hybrid`：RGB/ReID 负责确认目标身份，GT point/coordinate takeover 负责目标位置；原 B
  已经属于这一类，但其 Oracle controller 仍是特权上限。
- `B-point`：完全不运行 RGB/ReID，只提供目标点坐标给 Oracle navmesh；已由
  `PointPerception`（`PERCEPTION=point`）实现，命令见上。
- `D-point`：完全不使用 RGB/ReID 或 panoptic 身份，只提供目标点坐标给模块化控制；同样
  用 `PERCEPTION=point`（`PointPerception`），无需再拆 provider。`TARGET_MODE=auto` 在
  `PERCEPTION=point` 下会自动落到 `point`，显式指定 `TARGET_MODE=point` 亦可。
- `D-hybrid`：RGB/ReID 负责“跟谁”，外部或模拟 UWB 坐标负责“在哪里”，模块化控制器消费
  两者。当前实现坐标直接读取 Habitat `target_agent`（`local_target`），只可标为
  `oracle-coordinate` 上限；坐标应明确建模噪声、延迟或丢失后再做正式部署结论。
- `D-visual`：原 D，RGB-D 视觉目标点和模块化控制，不使用外部坐标；仅作为纯视觉消融，
  不代表混合部署系统。

当前结果表中的 `modular perception + oracle control` 是 `B-hybrid`，`all modular` 是
`D-visual`。`PERCEPTION=point` 的 point-only provider 已在 `oracle_modular_batch.py`
实现（`PointPerception`，不加载 RGB/ReID/panoptic）；`B-point`、`D-point` 已可按上文
命令直接评测，`D-hybrid` 当前以 GT 坐标为 oracle-coordinate 上限先行评测。

### 六种模式的调试视频

下面命令均只运行一个 AT episode 的前 60 步，先检查视频中的目标框、目标点、坐标接管和
控制模式。将 `DATASET_INDEX` 改为 `1`、`49`、`134` 或 `902` 可检查不同遮挡/多人场景。
六种模式必须使用不同的 `OUTPUT_ROOT`。

```bash

# B-visual: RGB/ReID 视觉点 + Oracle navmesh，禁止 GT 坐标接管

PYTHONPATH=habitat-lab:. \
./run_egl.sh "$PYTHON_BIN" -u oracle_modular_batch.py \
  --task at --split val --shard-id 0 --num-shards 1 \
  --dataset-index 49 --max-steps 60 \
  --output-root "$PWD/outputs/mode_b_visual_debug" \
  --perception rgb-person --controller oracle-navmesh --target-mode visual \
```
