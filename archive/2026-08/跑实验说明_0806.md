# OmTrackVLA 感知 × 控制实验计划（2026-08-06）

## 1. 目标

在训练新模型前，先建立感知与控制的二因素实验矩阵，分别测量感知误差、控制误差及二者
闭环耦合。所有最终结果使用相同 episode、相同距离阈值和相同 first-attempt 口径。

| 编号 | 感知 | 控制 | 作用 | 当前状态 |
|---|---|---|---|---|
| A | Oracle panoptic + GT point goal | Oracle navmesh | Privileged reference | 已完成 |
| B | 模块化 RGB-D detector/ReID | Oracle navmesh | 隔离感知损失 | 已完成 |
| C0 | Oracle GT point goal | direct reactive control | 无建图控制下界 | 已实现 |
| C1 | Oracle GT point goal + depth | local obstacle-map control | 隔离建图/避障控制损失 | prototype |
| D | 模块化 RGB-D detector/ReID | 模块化 reactive/learned control | 可部署闭环系统 | 下一阶段 |

对应分析：

```text
感知差距 = A - B
控制差距 = A - C
完整系统差距 = A - D
感知控制交互 = D - B - C + A
```

## 2. 输入与特权信息定义

### 2.1 Oracle navmesh control

可以读取目标 agent 世界坐标、Habitat navmesh 和 GT coordinate takeover，只作为 reference。

### 2.2 模块化 reactive control

控制器只读取 `TargetObservation` 中的局部 `relative_xy/range/bearing/visible` 和内部历史状态，
不读取 `target_agent`、目标 semantic ID、目标世界坐标或 navmesh shortest path。

C 使用 Oracle perception 提供的精确局部 point goal，即使目标暂时离开相机视野也继续提供
精确相对坐标。因此 C 同时也是 “PointGoal-only（无 RGB 定位误差）+ 模块化控制” baseline。

D 使用 RGB/RGB-D perception；目标丢失时没有 GT point goal，只能停止、搜索或使用历史预测。

## 3. 额外 baseline 与消融

最终论文建议包含：

1. RGB-only VLA：RGB/history + instruction 直接预测动作；
2. RGB-only modular：RGB detector/tracker + 单目距离 + 模块化控制；
3. RGB-D modular：RGB detector/ReID + sensor depth + 模块化控制；
4. PointGoal-only：精确相对目标向量 + 模块化/learned control；
5. no-ReID、no-temporal-memory、no-depth、no-lost-recovery 消融；
6. coordinate takeover 与 stop/search 的特权信息消融。

模块指标包括 detection recall、ID precision/recall、ID switch、range/bearing error 和恢复延迟；
系统指标包括 SR、TR、CR、距离误差、动作平滑度和计算吞吐。

## 5. C1：Ascent-style obstacle map prototype

C1 复用 Ascent 中有用的核心思路：`depth -> point cloud -> height filter -> obstacle
grid -> robot-radius inflation -> local waypoint`，但不引入 frontier/VLM/多楼层逻辑。

- 静态层：由 depth 投影，排除地板、天花板和机器人自身近场点；
- 动态层：行人当前帧实时更新，不写入 persistent static obstacle；
- 目标人：从静态层剔除，但在动态层保留安全半径，规划目标是距人
  `1.2--1.5 m` 的 follow ring，而不是人体中心；
- 视频：左侧 RGB 第一视角，右侧局部障碍地图；黑色为膨胀障碍，粉色为动态人体，
  红色为机器人，绿色为目标。

C1 已包含 episodic persistent map fusion、dynamic layer 逐帧刷新、robot-radius inflation
和 A* 局部路径。当持久地图因视角噪声暂时堵塞但当前 depth 走廊明显开放时，
控制器会进入 `map_live_depth_recovery`，并以低速重新追踪，避免在椅子/桌子前摆动。
后续仍可加入 dynamic TTL 和速度预测，以支持多行人与快速运动。

## 6. 后续研发顺序

1. 在 train/dev 的分层 100--200 episode 上稳定 C；
2. 跑 C 三任务全量，得到纯控制差距；
3. 将同一 reactive controller 接到 RGB-D perception，得到 D；
4. 根据 A/B/C/D 判断主要瓶颈；
5. 感知侧用 GT bbox、identity、range/bearing 蒸馏；
6. 控制侧用 Oracle action 做 BC，再用 DAgger/residual RL 处理闭环分布偏移；
7. 冻结方法后使用全新输出目录重跑最终 Val，并做 scene-cluster bootstrap 置信区间。

开发和调参应使用 train/dev，Val 只用于冻结后的最终评测。
