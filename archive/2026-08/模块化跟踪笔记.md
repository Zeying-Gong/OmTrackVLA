# OmTrackVLA 感知 × 控制实验计划（更新至 C4，2026-08-10）

## 1. 目标

在训练新模型前，先建立感知与控制的二因素实验矩阵，分别测量感知误差、控制误差及二者
闭环耦合。所有最终结果使用相同 episode、相同距离阈值和相同 first-attempt 口径。

| 编号 | 感知 | 控制 | 作用 | 当前状态 |
|---|---|---|---|---|
| A | Oracle panoptic + GT point goal | Oracle navmesh | Privileged reference | 已完成 |
| B | 模块化 RGB-D detector/ReID | Oracle navmesh | 隔离感知损失 | 已完成 |
| C0 | Oracle GT point goal | direct reactive control | 无建图控制下界 | 已实现 |
| C1 | Oracle GT point goal + depth | 初版 local obstacle-map control | 建图/避障原型 | 已实现 |
| C2 | Oracle GT point goal + depth | 保守二维地图 + A* | Spot 建图校准版 | 已完成校准 |
| C3 | Oracle GT point goal + depth | C2 + 安全规划 + 行人轨迹记忆 | C4 前代基线 | 已完成全量 |
| C4 | Oracle GT point goal + depth | C3 + 动态行人安全层 | Rule-based 控制基线 | 已完成全量 |
| D | 模块化 RGB-D detector/ReID | 模块化 reactive/learned control | 可部署闭环系统 | 下一阶段 |

对应分析：

```text
感知差距 = A - B
控制差距 = A - C
完整系统差距 = A - D
感知控制交互 = D - B - C + A
```

## 2. 输入与特权信息定义

### 2.1 Oracle navmesh control

可以读取目标 agent 世界坐标、Habitat navmesh 和 GT coordinate takeover，只作为 reference。

### 2.2 模块化 reactive control

控制器只读取 `TargetObservation` 中的局部 `relative_xy/range/bearing/visible` 和内部历史状态，
不读取 `target_agent`、目标 semantic ID、目标世界坐标或 navmesh shortest path。

C 使用 Oracle perception 提供的精确局部 point goal，即使目标暂时离开相机视野也继续提供
精确相对坐标。因此 C 同时也是 “PointGoal-only（无 RGB 定位误差）+ 模块化控制” baseline。

D 使用 RGB/RGB-D perception；目标丢失时没有 GT point goal，只能停止、搜索或使用历史预测。

## 3. 额外 baseline 与消融

最终论文建议包含：

1. RGB-only VLA：RGB/history + instruction 直接预测动作；
2. RGB-only modular：RGB detector/tracker + 单目距离 + 模块化控制；
3. RGB-D modular：RGB detector/ReID + sensor depth + 模块化控制；
4. PointGoal-only：精确相对目标向量 + 模块化/learned control；
5. no-ReID、no-temporal-memory、no-depth、no-lost-recovery 消融；
6. coordinate takeover 与 stop/search 的特权信息消融。

模块指标包括 detection recall、ID precision/recall、ID switch、range/bearing error 和恢复延迟；
系统指标包括 SR、TR、CR、距离误差、动作平滑度和计算吞吐。

## 5. C1：Ascent-style obstacle map prototype

C1 复用 Ascent 中有用的核心思路：`depth -> point cloud -> height filter -> obstacle
grid -> robot-radius inflation -> local waypoint`，但不引入 frontier/VLM/多楼层逻辑。

- 静态层：由 depth 投影，排除地板、天花板和机器人自身近场点；
- 动态层：行人当前帧实时更新，不写入 persistent static obstacle；
- 目标人：从静态层剔除，但在动态层保留安全半径，规划目标是距人
  `1.2--1.5 m` 的 follow ring，而不是人体中心；
- 视频：左侧 RGB 第一视角，右侧局部障碍地图；黑色为膨胀障碍，粉色为动态人体，
  红色为机器人，绿色为目标。

C1 已包含 episodic persistent map fusion、dynamic layer 逐帧刷新、robot-radius inflation
和 A* 局部路径。当持久地图因视角噪声暂时堵塞但当前 depth 走廊明显开放时，
控制器会进入 `map_live_depth_recovery`，并以低速重新追踪，避免在椅子/桌子前摆动。
后续仍可加入 dynamic TTL 和速度预测，以支持多行人与快速运动。

## 6. C2/C3：Spot 保守二维建图与轨迹记忆控制

C2 完成了 Spot 深度建图校准；C3 在 C2 基础上加入安全规划、行人历史轨迹和规划稳定性修复。代码参数仍为：

```text
--controller map-reactive-vlfm
```

C3 当前逻辑：

- Spot 相机高度/前向偏移均为 `0.24 m`，HFOV 为 `90°`；
- 障碍高度带 `0.20–1.20 m`，地图 `20 m × 20 m`，分辨率 `10 cells/m`；
- 默认保存整个 episode 的地图记忆，使用保守二维 free-space；
- 静态家具进入持久层，当前所有行人进入逐帧动态层，不固化为墙；
- 近场补充检测只接收 `0.90 m` 内且高度至少 `0.10 m` 的返回，避免漏掉近家具并继续过滤地面；
- 第三栏显示原始障碍地图，但 A* 内部使用 Spot `0.30 m` 安全半径；
- A* 路径前方约 `0.55 m` 选 carrot，最终输出 `(Vx,Vy,Vyaw)`；
- 距离误差控制追赶速度，并带 `0.12 m/s` 有限 catch-up 前馈；
- 记录最近约 24 个可见帧的行人轨迹。当前目标被墙/拐角隔断时，优先选择最新且可达的历史点作为中间目标；跳过机器人后方超过 `0.20 m` 的旧点；中间目标锁定到直线重新畅通，避免每帧切换产生绕路；
- `1.50–1.70 m` 使用迟滞保持，只朝向行人，不启动完整 A*。超过 `1.70 m` 才重新规划，避免近距离目标产生几十至上百格的异常路径。

## 7. C3 全量诊断与 C4

C3 三任务 Val 全量结果：

| Task | Episodes | Success | Tracking | Collision | Finish |
|---|---:|---:|---:|---:|---:|
| STT | 1405 | 0.6313 | 0.7794 | 0.0463 | 0.9537 |
| DT | 1405 | 0.5317 | 0.6832 | 0.0399 | 0.9601 |
| AT | 1405 | 0.6093 | 0.7536 | 0.0441 | 0.9559 |

失败主体不是碰撞。STT/DT/AT 分别有 453/602/487 个“正常结束、无碰撞但跟随率不足”的失败，碰撞仅有 65/56/62 个。低跟随 index 在三个任务间高度重复，说明主要瓶颈是局部建图/控制，而不是 AT 身份切换。

代表性诊断：

- AT index 1：C3 在 11 步时从 `1.84 m` 接近到 `0.46 m` 并撞人。C3 过近时只反转 `Vx`，`Vy` 仍朝行人，且迎面行人速度与机器人后退速度接近；
- AT index 155：300 步、tracking `0`，其中 237 步为 `map_blocked`。局部地图/NavMesh IoU `0.387`，`unsafe_free_rate=0.507`，深度局部图无法表达 Spot 对家具和狭缝的实际可达性；
- AT index 584：136 步、tracking `0.0368`，目标只可见约 6 帧后跨房间离开。短行人历史只覆盖门口，局部地图没有足够信息恢复后续全局路线。

C4 使用独立的 `--controller map-reactive-c4`，保留 C3 建图和 A*，新增动态行人安全层：

- 在 episode 坐标中估计行人自身二维速度，避免把机器人主动接近误判为行人迎面靠近；
- 预测未来 5 步的最近会遇距离，而不是只看当前距离或径向速度；
- 预计中心距离小于 `0.65 m` 时接管，斜向目标沿二维反方向撤离，持续迎面目标锁定空旷侧横向让行；
- 当前距离恢复到安全带且预计最近距离超过 `0.90 m` 后立即释放，避免长期避让损失 tracking；
- C3 controller 行为保持不变。

2026-08-10 冻结版本还包含：

- Oracle panoptic 同一 semantic ID 出现多个连通域时，使用真实 RGB 相机投影、组件深度和时序关联选择目标；目标框为红色，其他行人或镜像连通域为蓝色；
- 所有可见行人均从持久静态障碍层排除，只进入逐帧动态层，避免把非目标行人固化为墙；
- 每步 JSON 记录目标组件、A* 路径、行人速度、motion-block 和 visibility portal 等诊断信息；
- AT index 902 已逐帧确认红框保持在真实目标、蓝框保持在另一人体/镜像区域，没有后半程身份互换；
- AT index 134 仍会在动态会车和跨房间遮挡后选择错误拓扑分支，是 C4 rule-based 控制的代表性失败，不加入 episode 特例修补。

AT index 1 的 C4 回归为 47 步正常完成，`success=1.0`、`tracking=1.0`、`collision=0.0`。index 155/584 暴露的是局部地图缺少全局可达性，不在本次 C4 中宣称解决。

## 8. 后续研发顺序

1. 用户检查 C3 文档和异常路径短回归；
2. 重新完整回归 index 0、49、100、200，冻结 C3 参数；
3. 在 train/dev 的分层 100--200 episode 上稳定 C3；
4. 跑 C3 三任务全量，得到纯控制差距；
5. 将同一 C3 controller 接到 RGB-D perception，得到 D；
6. 根据 A/B/C3/D 判断主要瓶颈；
7. 感知侧用 GT bbox、identity、range/bearing 蒸馏；
8. 控制侧用 Oracle action 做 BC，再用 DAgger/residual RL 处理闭环分布偏移；
9. 冻结方法后使用全新输出目录重跑最终 Val，并做 scene-cluster bootstrap 置信区间。

开发和调参应使用 train/dev，Val 只用于冻结后的最终评测。
